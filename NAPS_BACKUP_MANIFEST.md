# Резервная копия NAPS 0.6.0

Дата: 2026-10-11. Резервная копия создана и проверена перед продолжением модернизации по новому требованию пользователя.

- Исходная ветка: `codex/naps-editor-eskd`.
- Исходный HEAD: `3e9af03dd24ecbb86ff98a42c680b28fc035d311`.
- Резервная ветка: `backup/naps-0.6.0-before-modernization` (указывает на исходный HEAD).
- Независимая файловая копия: `D:\NAPS_0.6.0_BACKUP`.
- Рабочая ветка дальнейшей разработки: `codex/naps-modernization`.

## Что сохранено

Скопированы исходники, конфигурации, ресурсы, встроенные библиотеки, тесты, документация, все текущие изменённые и неотслеживаемые файлы проекта, каталог `.git` с историей и индексом, а также существующий каталог `release`. Снимок включает уже выполненные до нового требования правки проводов, прямого режима, печати и пространственного поиска. Он не выдаётся за состояние до начала всей переписки.

Дополнительно сохранены каталоги пользовательских настроек `%APPDATA%\naps-cad` и `%APPDATA%\voltaris-cad` в `_user_settings` внутри копии. Данные отдельного браузерного профиля за пределами этих каталогов не копировались.

Исключены воспроизводимые зависимости `node_modules`, production-каталог `dist`, временный `.work`, `coverage` и `resume_audit_rendered`. Для установки зависимостей сохранён `package-lock.json`. Ресурсный каталог `build` сохранён.

Обычная резервная ветка не содержит незакоммиченные изменения; их полное содержимое сохранено файловой копией. Поэтому для восстановления именно этого снимка следует использовать файловую копию, а не только переключение ветки.

## Проверка целостности

SHA-256 всех 773 сохранённых файлов проекта сравнены с исходниками: совпадение для каждого файла. Файлы настроек также сравнены с исходными по SHA-256. Контрольная ведомость проекта находится в `D:\NAPS_0.6.0_BACKUP\BACKUP_SHA256.json`. `git fsck --full` в копии завершился с кодом 0; сообщения о dangling tree относятся к несвязанным объектам истории, ошибок повреждения не обнаружено.

Резервный каталог после проверки не используется для разработки и не изменяется. Новые сборки должны помещаться в отдельный подкаталог `release`, без перезаписи двух исходных EXE.

## Исходные проверки после создания снимка

`npm run lint`, `npm test` и полный `npm run test:browser` завершились успешно до новых изменений после резервирования. Браузерный набор включает прежние сценарии проводов, 50 Undo/Redo, новый прямой провод, редактор, расчёты, AC, экспорт и транзисторы. Эти результаты являются исходной точкой дальнейшего сравнения.

## Безопасное восстановление и сравнение

1. Скопировать `D:\NAPS_0.6.0_BACKUP` в новый пустой каталог, например `D:\NAPS_0.6.0_RESTORED`; не накладывать его на текущую рабочую папку.
2. Проверить SHA-256 по `BACKUP_SHA256.json`.
3. В восстановленной копии выполнить `npm ci`, затем `npm run dev` или `npm run electron:start`. Это воспроизводит исходники снимка с сохранёнными незакоммиченными правками.
4. Для запуска ранее собранной версии использовать копию сохранённого Portable EXE. Он может использовать существующий профиль настроек; перед сравнительным запуском сохранить текущий профиль или использовать отдельную учётную запись ОС.
5. Для возврата настроек закрыть приложение, сохранить новый профиль отдельно и скопировать нужный профиль из `_user_settings` в соответствующий каталог `%APPDATA%`. Автоматической перезаписи текущих настроек не выполнялось.

Старые SCM-файлы следует открывать из копий. Команды сброса, очистки, удаления исходников и Git push при создании снимка не применялись.
