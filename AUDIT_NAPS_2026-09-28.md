# NAPS — технический аудит до исправлений

Дата: 28 сентября 2026 года. Проект: `D:\FASTMEAN 2.0`, ветка `main`. Исходный код и существующие файлы не менялись. Проверялась браузерная версия на отдельном локальном порту 3131; Windows EXE и установщик не запускались. Термины «подтверждено», «риск» и «не проверено» ниже имеют разный смысл: подтверждённые проблемы воспроизведены указанным способом, риски следуют из кода или конфигурации без доказанного отказа, а непроверенные области не получили достаточного покрытия.

## 1. Карта проекта и общая картина

NAPS — локальный редактор электрических схем. Один экран React/TypeScript содержит SVG-редактор, библиотеку компонентов, параметры моделирования, графики, формулы и экспорт. Основные связи:

| Область | Реализация |
| --- | --- |
| Состояние проекта, история, файл, расчёт | `src/App.tsx` |
| Холст, проводка, сетка, библиотека быстрого доступа, горячие клавиши | `src/components/SchematicEditor.tsx`, `ComponentPalette.tsx`, `ComponentSymbol.tsx` |
| Формат SCM | `src/utils/yamlScm.ts`, `ScmYamlModal.tsx` |
| Электрическая связность | `buildCircuitGraph` в `src/math/circuitSolver.ts` |
| Линейный расчёт | `src/math/linearTransient.ts` через `src/math/simulation.worker.ts` |
| Специализированные учебные модели | `src/math/circuitSolver.ts`, примеры `src/data/sampleCircuits.ts` |
| Графики, формулы, выгрузка | `GraphWindow.tsx`, `CalculationDetails.tsx`, `calculationReport.ts` |
| Настольная оболочка | `index.js`, `electron/preload.cjs`, `electron-builder` в `package.json` |

Стек: React 19, TypeScript 5.8, Vite 6, Tailwind CSS 4, Electron 44, Playwright Core. Маршрутов страниц, собственного backend, сетевых API, базы данных, пользовательских аккаунтов и ролей в текущем приложении нет. Единственный доступ к файлам в настольной версии — два IPC-вызова открытия и сохранения `.scm`; браузерная версия использует File API и скачивание. Горячие клавиши сохраняются в `localStorage`, схема автоматически не сохраняется. Поэтому проверка HTTP-статусов, транзакций, SQL-инъекций, CSRF и разграничения ролей к этой архитектуре неприменима.

Документация: `README.md`, `LICENSE`, прежний `AUDIT_NAPS_2026-09-25.md`; тесты в `scripts/`; CI в `.github/workflows/ci.yml`. README явно ограничивает нелинейные модели исходной топологией примеров, а AC/Bode сейчас недоступен. Нельзя считать эти ограничения регрессией без отдельного требования. Формальной спецификации для всех 22 типов компонентов, целевых требований к доступности и нагрузке нет. README отмечает отсутствие опубликованных скриншотов.

Перед выпуском исправления требуют прежде всего четыре подтверждённых дефекта данных и расчёта: неверное числовое толкование номинала, некорректные координаты SCM, повтор имён компонентов и настройки сигналов примера в новом проекте. Проверенные маршруты проводки и базовые расчётные примеры прошли существующие тесты, но это не доказывает отсутствие иных ошибок.

## 3. Реестр подтверждённых проблем

### NAPS-01 — настройки первого примера делают расчёт новой простой схемы невозможным

- Категория: функциональность/расчёт. Критичность: **High**.
- Файлы: `D:\FASTMEAN 2.0\src\App.tsx:23-26`, `D:\FASTMEAN 2.0\src\math\linearTransient.ts:151-160`, `D:\FASTMEAN 2.0\src\components\TransientSetupModal.tsx:30-48`.
- Шаги: открыть новый пустой проект; создать электрически корректную цепь из источника 12 В, резистора 1 кОм и земли; нажать «Рассчитать схему», не меняя параметры сигналов.
- Ожидалось: расчёт цепи и доступный график, либо автоматический выбор существующего сигнала.
- Фактически: `Не найден сигнал U(2)`. Браузерная проба с импортированной корректной трёхэлементной цепью дала именно это сообщение. Прямой вызов `solveCircuitTransient` с настройками нового проекта подтвердил тот же отказ. Исходные сигналы — `U(2)`, `U(4)`, `I(L1)`, `I(R3)`.
- Первопричина: пустой проект получает `transient` из `SAMPLE_CIRCUITS[0]`; список сигналов не перестраивается при изменении схемы. В окне настроек также зашиты демонстрационные имена и номера узлов.
- Исправление: нейтральные настройки нового проекта и построение предложений сигналов из актуального графа; при расчёте явно уведомлять о несоответствующих пользовательских выражениях без их тихой подмены.

### NAPS-02 — неверный суффикс номинала принимается как другое число

- Категория: целостность данных/неверный расчёт. Критичность: **High**.
- Файлы: `D:\FASTMEAN 2.0\src\math\circuitSolver.ts:19-63`, `D:\FASTMEAN 2.0\src\components\ElementPropertiesModal.tsx:80-99`.
- Шаги: добавить резистор, открыть свойства, ввести `1кк`, подтвердить, сохранить SCM.
- Ожидалось: ошибка формата, значение не изменяется.
- Фактически: на схеме показывается `1кк`, а SCM содержит `Value: "1"` и `ValueText: "1кк"`; расчёт использует 1 Ом. Повторено в Chrome, скачанный SCM прочитан тестом.
- Первопричина: регулярное выражение `parseEngValue` не привязано к концу строки, а неизвестный суффикс в `default` возвращает числовую основу. Форма не проверяет совпадение введённого текста с допустимой грамматикой и физическими ограничениями до записи.
- Исправление: строгий разбор всей строки с явной ошибкой, проверка диапазонов по типу элемента, одинаковая валидация формы и SCM.

### NAPS-03 — после удаления элемента автоматически создаётся занятое имя

- Категория: редактор/расчёт. Критичность: **High**.
- Файлы: `D:\FASTMEAN 2.0\src\components\SchematicEditor.tsx:812-816,945-973`, `D:\FASTMEAN 2.0\src\math\linearTransient.ts:101-103`.
- Шаги: поместить три резистора R1, R2, R3; удалить R2; добавить ещё один резистор.
- Ожидалось: новое уникальное имя, например R4.
- Фактически: получены `R1, R3, R3`. Браузерная проба зафиксировала последовательность имён до и после. Расчётный модуль откажется рассчитывать схему с повторными именами электрических элементов.
- Первопричина: очередной номер берётся как `existingSameType.length + 1`, а не как свободный/монотонный номер. Сохранение имени в свойствах также не проверяет уникальность.
- Исправление: общий генератор уникальных имён по текущим обозначениям с проверкой без учёта регистра и валидация ручного переименования.

### NAPS-04 — SCM принимает нечисловую координату и помещает в холст `NaN`

- Категория: импорт/целостность схемы. Критичность: **High**.
- Файлы: `D:\FASTMEAN 2.0\src\utils\yamlScm.ts:311-315,479-485`, `D:\FASTMEAN 2.0\src\components\ScmYamlModal.tsx:60-69`.
- Шаги: в редакторе SCM задать объекту `X: wrong`, `Y: 100`, нажать «Применить схему из YAML».
- Ожидалось: сообщение с номером объекта и отказ от импорта без замены проекта.
- Фактически: окно закрывается без ошибки, SVG-элемент получает `transform="translate(NaN, 100)"`. В прямой пробе парсер вернул не конечное число для X.
- Первопричина: `parseInt`/`parseFloat` применяются без проверки полного формата и `Number.isFinite`; собранный объект сразу передаётся редактору. Та же зона кода требует проверки Y, поворота и всех числовых параметров.
- Исправление: атомарная валидация всего SCM перед `replaceProject`; обязательные поля и диапазоны, конечные координаты и поворот, строгая диагностика по строке/ID. Сохранять прежнюю схему при ошибке.

### NAPS-05 — клавиатурный фокус уходит под открытый модальный диалог

- Категория: доступность/UI. Критичность: **Medium**.
- Файлы: `D:\FASTMEAN 2.0\src\components\SchematicEditor.tsx:1864-1868` и разметка библиотеки ниже; аналогичные диалоги требуют проверки.
- Шаги: открыть «Библиотека», из автосфокусированного поиска дважды нажать Shift+Tab.
- Ожидалось: фокус остаётся внутри модального окна и возвращается на вызывающую кнопку после закрытия.
- Фактически: после кнопки закрытия фокус переходит на фоновую кнопку «Параметры расчета»; следующие нажатия обходят фон. Подтверждено в Chrome. При открытии свойств текущий фокус также остаётся на BODY до первого Tab.
- Первопричина: `aria-modal="true"` добавлено, но управление фокусом, ловушка Tab и возврат фокуса не реализованы.
- Исправление: единый доступный компонент диалога, начальный фокус, циклический Tab/Shift+Tab, Escape, восстановление фокуса.

## 5. Отчёт по интерфейсу

- **UI-01, подтверждённое функциональное несоответствие:** модальная библиотека заявлена через `aria-modal`, но клавиатурный фокус уходит на фон (NAPS-05). Для пользователей клавиатуры и вспомогательных технологий это нарушает последовательность действий.
- **UI-02, визуальная несогласованность, Low:** библиотека использует новую светлую карточную компоновку, а окно параметров переходного процесса и окно свойств сохраняют плотный старый стиль с яркой синей шапкой, красной кнопкой закрытия и мелким текстом. Снимки: `.work/audit-20260928/browser-library-900.png`, `.work/audit-20260928/properties-900.png`, `.work/audit-20260928/transient-900.png`. Привести диалоги к общим размерам кнопок, полей и типографике, сохранив компактность инженерных таблиц.
- **UI-03, условный риск браузерного использования:** при ширине 600 px часть правых элементов панели не видна на снимке `.work/audit-20260928/viewport-600.png`. В desktop `index.js:17-18` минимальная ширина окна 900 px, поэтому это не дефект заявленной Windows-платформы. Если браузер на планшете/телефоне входит в цель выпуска, нужна отдельная компактная панель; без такого требования статус остаётся непроверенной пригодностью для мобильных.
- При 900×650 клетчатая сетка, статус-бар и основные действия видимы (`.work/audit-20260928/viewport-900.png`). Снимки проводов: `.work/audit-20260928/browser-crossing.png` и `browser-crossing-junction.png`. Автоматическая проверка контрастности WCAG, экранные дикторы и масштабирование до 200–400% не проводились, поэтому полная доступность не заявляется.

## 7. Приоритетный план исправлений и регрессия

1. **Строгая валидация данных до расчёта и импорта.** Исправить NAPS-02 и NAPS-04 общими правилами чисел, диапазонов и целостности SCM. Проверить, что исходная схема не заменяется при любой ошибке. Регрессия: допустимые `1k/1к/1М/1мк`, неизвестные суффиксы, пробелы, NaN/Infinity, неверные X/Y/Rot/Value, импорт всех шести примеров и повторный экспорт.
2. **Корректное создание новой схемы и идентификаторов.** Исправить NAPS-01 и NAPS-03. Регрессия: новая цепь V+R+GND рассчитывается без ручной настройки сигналов; после удаления среднего элемента новое имя уникально; ручное переименование с конфликтом отклоняется; undo/redo и SCM сохраняют ссылки проводов.
3. **Электрическая регрессия после любых правок модели.** Повторить автоматические и браузерные сценарии пересечения, Т-ветви, параллельных ветвей, диагонали, редактирования сегмента, перемещения/поворота и SCM; сравнить видимые конечные точки с `buildCircuitGraph`.
4. **Доступность и визуальная унификация.** Исправить NAPS-05, затем UI-02. Регрессия: Tab/Shift+Tab не выходит из каждого модального окна; Escape/закрытие возвращает фокус; проверка 900×650, 1440×900 и, при решении поддерживать браузерные узкие окна, 600×800 и масштаб 200%.
5. **Усиление выпуска.** Проверить CSP в собранном Electron, затем R-02 в отдельном файловом стенде; добавить браузерную регрессию в CI. После исправлений отдельно пересобрать установщик и portable EXE и проверить их запуск, открытие/сохранение SCM и поведение при ошибке записи, если пользователь разрешит проверку EXE.
6. **Технический долг после стабилизации.** Уточнить назначение неиспользуемых компонентов, разделить чистые вычисления и UI-состояние в большом редакторе; добавить измерения для 800+ элементов и схем около предела 160 неизвестных.

## 8. Непроверенные области и необходимые условия

- Реальная установка, запуск portable EXE, работа IPC и сохранение файлов в Windows, подпись дистрибутива и реакция SmartScreen: нужен отдельный этап проверки настольной версии. Успешная Vite-сборка этого не подтверждает.
- Нелинейные модели вне топологий встроенных примеров не поддерживаются по README; физическая точность специализированных моделей относительно независимого эталонного симулятора не оценивалась. Нужны эталонные схемы/ожидаемые результаты преподавателя и профильная инженерная верификация.
- Состав зависимостей проверен `npm audit`, но не проведён независимый анализ состава пакета Electron, code signing и динамический security-тест. Активных атак на внешние сервисы не было, внешних сервисов в проекте не обнаружено.
- Длительная сессия, прерывание ОС во время записи SCM, очень большие файлы, 800+ элементов, замер памяти/профилирование CPU, слабое устройство и масштаб 400% не проверены достоверно. Нужны изолированные тестовые файлы, профилировщик и отдельный нагрузочный стенд.
- Скринридеры и автоматическая проверка WCAG/контраста не запускались; пригодность для мобильного браузера продуктово не определена. Браузерная версия работала локально, поведение на публичном хостинге не проверялось.

Вывод ограничен указанными методами и сценариями: успешные проверки подтверждают работу именно проверенных случаев, а отсутствие иных найденных дефектов не является доказательством их отсутствия.
