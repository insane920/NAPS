# NAPS: план исправлений и проверки ТЗ

Состояние на 31.10.2026. До новой правки матрица содержала 39 проверенных и 11 частичных пунктов. W06 временно открывался и затем закрыт после браузерной проверки; W01 закрыт после проверки безопасного сохранения повреждённого SCM 8. Сейчас 40 проверенных и 10 частичных. По отдельному запросу пользователя 31.10.2026 установщик и portable EXE пересобраны из текущего кода; запуск самих EXE ещё не проверен.

## Правила работы

1. Сохранить текущее рабочее дерево; Git и коммиты не входят в работу.
2. После каждого исправления проверять не только видимую линию, но и `buildCircuitGraph`, сохранение SCM 7/8 и Undo/Redo.
3. Для старых SCM 7 пересечения сохраняют старую семантику; в новых SCM 8 пересечение активных проводов создаёт электрическое соединение.
4. При сбое маршрутизации отменять действие с понятной диагностикой. Нельзя показывать соединение, которого нет в расчётном графе.
5. Каждый пункт матрицы закрывать только после проверки полного пользовательского сценария. Непроверенные результаты оставлять частичными.

## Этап 0. Контроль исходного состояния

- Зафиксировать список изменённых файлов и текущие результаты `npm run lint`, `npm run test`, `npm run build`.
- Разобрать четыре предоставленных снимка в воспроизводимые SCM 8 схемы: GND, аномальный обход, перетаскивание участка, пересечение.
- Для каждого сценария записать исходные координаты, провода, ожидаемое число узлов/циклов и видимые сегменты.
- Восстановить доступ браузерных тестов в разрешённой Windows-среде. Пока `npm run test:browser` не проходит, не считать работу редактора подтверждённой.

## Этап 1. Проводка и GND — приоритет P0

| Задача | Исправление | Проверка завершения |
| --- | --- | --- |
| GND не требуется | Проверить неявную опорную точку во всех DC/transient/AC решателях; убрать возможность случайной установки GND в новой схеме; сохранить старые символы и их соединения при открытии SCM | Замкнутые R, RC и RL цепи без GND дают те же токи и разности потенциалов, что эквивалентные схемы с GND; старый SCM открывается без изменения графа |
| Прямые пересечения SCM 8 | Убедиться, что маршрутизатор не обходит чужой провод лишь ради избегания пересечения; нормализовать X/T/наложение в явную точку электрического графа | На экране один маркер в месте соединения; `pinToNode` объединяет сети; после удаления/переноса пересечения сети разделяются; SCM 7 неизменён |
| Перетаскивание участка ЛКМ | Редактировать всю связанную геометрию участка: соседние ортогональные плечи, общие сегменты и присоединённые ветви; сохранять фиксированные выводы и ручные изгибы | При переносе внутренней «палочки» не добавляются лишние углы, ветвь не отрывается; один Undo/Redo восстанавливает геометрию и электрический граф |
| Аномальные петли | Проверить выбор прямой, L и Z перед сложным обходом; не принимать старый маршрут из кеша, если геометрия или препятствия изменились | Схемы со снимков, плотная сеть и 50 повторных переносов не накапливают изгибы; провод не проходит сквозь тело элемента |
| Границы и устойчивость | Разветвления, общий участок в обратных направлениях, циклы, совпавшие узлы и нулевые сегменты | Число связных компонент и независимых циклов меняется только при явном изменении соединения; SCM 8 round-trip и Undo/Redo проходят |

Для этого этапа использовать `scripts/check-wiring-audit.ts`, `browser-p0-routing.cjs`, `browser-w09-cycles.cjs`, `browser-reconnect.cjs`, `browser-manual-waypoint.cjs` и новые браузерные сценарии по четырём снимкам. Текущая правка перетаскивания внутреннего участка не доказывает работу общего сегмента разветвлённой сети — это отдельный критерий.

## Этап 2. Повторная приёмка уже отмеченных пунктов

Проверить основные сквозные сценарии: разместить пять двухполюсников, сменить варианты, соединить, изменить параметры, переместить и повернуть, сохранить SCM, открыть, посчитать DC/transient/AC, экспортировать. Если воспроизведётся дефект в пункте со статусом «проверено», вернуть его в «частично» и исправить. Особое внимание W01/W05 и соответствию видимой топологии расчётной.

## Этап 3. Оставшиеся 10 пунктов матрицы

| ID | Что требуется для закрытия |
| --- | --- |
| W05 | Проверить плотные схемы и отказ при превышении бюджета поиска; определить реалистичный критерий оптимальности и отсутствие ложного отказа на контрольных схемах. |

| P02 | Решить попадание повёрнутых выводов на сетку без изменения старой геометрии и электрической модели; проверить миграцию. |
| P03 | Проверить крайние масштабы, прокрутку и touchpad в реальном интерфейсе. |
| P04 | Визуально проверить A0–A2, длинные подписи, печать и физические размеры; бумажный замер требуется отдельно. |
| E01 | Сверить внутренние и дополнительные графы основной надписи с применимым стандартом. |
| E02 | Сверить символы C, L, источников и повороты с нормативной геометрией. |
| E03 | Проверить физическую высоту и интервалы шрифта, кириллицу и полный набор обозначений в SVG/PDF. |

Для нормативных пунктов сначала сверить действующую редакцию стандартов и конкретные рисунки/размеры. Протокол замеров добавить в `NAPS_ESKD_AUDIT.md`; визуального сходства недостаточно.

## Этап 4. Полный регрессионный набор

1. `npm run lint`, `npm run test`, `npm run build`.
2. `npm run test:browser` в среде, где браузер действительно подключается к localhost; отдельно повторить четыре пользовательских случая.
3. Сохранить и повторно открыть SCM 7 и SCM 8, сравнить исходные и конечные сети, параметры, маршруты и результаты расчёта.
4. Проверить PDF/SVG на A0–A4, масштаб 1:1 и вписывание, векторность, кириллицу и монохромный режим.
5. Обновить матрицу только по пройденным проверкам; перечислить непроверенное и причину.
